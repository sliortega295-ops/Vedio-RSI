# Phase 3 independent Cache reverify transport — design only

Status: **DESIGNED / NOT IMPLEMENTED / NOT RUN**. The archived
`orchestration/bin/verify_delivery.py` must remain unchanged and be run by the
same seq0002 Master after a real Cache `DELIVERY.json` exists. It recomputes
authoritative speed from frozen `BASELINE.json` plus the durable run benchmark;
on a lossy point it calls `reassess()` through `PLAN_EVAL_PYTHON` and requires
numeric `lpips_max`. Master independently decides visual quality. The current
Master-local Python lacks the authorized Torch/LPIPS/AlexNet evaluation stack,
so simply setting `PLAN_EVAL_PYTHON=python3` would not be an independent judge.

The minimal site adaptation is an executable `PLAN_EVAL_PYTHON` shim for the
verifier's **single fixed** invocation shape. It must validate every argv
field (`search/plan_eval.py`, fixed model, `--no-gemini`, `--assess`, exact
seq0002 Cache R01/R02 run, frozen baseline-frames path, and
`--out=<same run>/reverify_verdict.json`); reject arbitrary commands, paths,
extra options, or GPU requests. It must submit one typed `reassess_quality`
request through the coordinator broker queue. The host broker may allow this
operation from the exact seq0002 Master/coordinator queue **only** for the
Cache run explicitly named in a real `DELIVERY.json` frontier point; the
existing Executor queue/submit/status/sync rules remain unchanged. A sandboxed
Master never sends SSH or executable text to the host daemon.

Host transport should validate the initial R01/R02 first-evaluation receipts
and their full pre/post SHA chain, plus current source/interpreter/dependency,
80-frame/video/run-config hashes. Current post hashes must match one explicitly
coordinator-accepted predecessor; arbitrary collector-generated bytes must
not be trusted. The trusted remote worker then runs the original archived
collector **once** with the frozen dense frames, followed by the original
`plan_eval --no-gemini --no-refresh-collection` against that refreshed quality
file. This is equivalent to the verifier's original one-refresh `reassess`
call, without a second redundant refresh. The worker must write the requested
`reverify_verdict.json` in the real remote run, with socket-deny active for all
subprocesses and no CUDA-visible devices. It must preserve full pre/post
snapshots, selected LPIPS pair indices and prompt distribution, child CPU and
wall times, network audit, and its own receipt. The host pulls only small
JSON/log files, verifies their SHA, and atomically syncs the exact requested
`reverify_verdict.json` plus original collector files into the same local real
run. Every subsequent reassess needs a newly accepted predecessor receipt
and exact post-hash pins; collector byte idempotence is **not** assumed.

The shim returns the original `plan_eval` process exit status and no synthetic
verdict. `verify_delivery.py` still reads `reverify_verdict.json`, checks
numeric LPIPS, and independently recomputes frozen speed; its source/objective
rules are untouched. The original collector may still report
`nvidia_gemini:api_key_missing` and standalone site-profile `plan_eval` may
still report `baseline_total_s=null`; neither is silently rewritten. Master
must separately apply the archived orchestration-lite visual gate using real
pixel-visible input (hash-locked `codex exec --image` site transport) and
record any unresolved graph/lite contract difference. Do not implement or run
this route until a genuine Cache DELIVERY requires native re-verification and
the coordinator reviews the exact post-hash predecessor pins.
