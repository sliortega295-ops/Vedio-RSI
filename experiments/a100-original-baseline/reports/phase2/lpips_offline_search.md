## Hidden pretrained-weight fetch guard (read-only review)

The official LPIPS source's default `LPIPS(net='alex')` sets `pnet_rand=False`, so its backbone construction calls `pretrained_networks.alexnet(pretrained=True)`, which in turn calls `torchvision.models.alexnet(pretrained=True)`. It separately loads bundled LPIPS linear weights from `lpips/weights/v0.1/alex.pth`. Therefore installing only the small `lpips` package can still cause an **implicit Torchvision AlexNet backbone fetch** when the archived judge first initializes it. Sources: [official LPIPS initialization](https://github.com/richzhang/PerceptualSimilarity/blob/master/lpips/lpips.py), [official AlexNet trunk](https://github.com/richzhang/PerceptualSimilarity/blob/master/lpips/pretrained_networks.py), and this project's `repo/tools/vision/lpips_judge.py:63–73`. This is a source-derived risk, not a download observed in this audit.

On both separately authorized A100 nodes, read-only checks with the known `/tmp/distillschedule-helios-official-torch210/bin/python` (Torch 2.10.0+cu128) resolved Torch hub to `/root/.cache/torch/hub` and found **no** `checkpoints/alexnet-owt-7be5be79.pth` there. The old locally authorized AlexNet asset has the expected SHA256 prefix `7be5be79`, but it is not in either remote Torch hub cache; it was not copied or installed. Merely setting `HF_HUB_OFFLINE=1` is insufficient to guard Torchvision's separate download path. Before any future exact judge invocation, a trusted host-side test must positively resolve both the package-bundled `weights/v0.1/alex.pth` and the AlexNet checkpoint in the *actual evaluation interpreter/cache*, set network-deny controls, and fail closed if either is absent. Any staging of the old backbone across hosts, if ever required, needs separate user authorization; package-only proxy approval does not authorize weight transfer or download.
