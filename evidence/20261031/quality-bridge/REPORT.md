# Cache 跨轮对照：速度复现，旧质量结论出现分歧

本次固定配方对照已完成，**没有新增质量通过的优化点**。最重要的发现是：
旧 Cache 能原样复现，但此前“质量通过”的判断，在同一套 rubric 的独立匿名复评中没有成立。
不能把旧方案约 1.47× 与较保守方案约 1.29×，直接当作同质量条件下的搜索进步／退步。

## 1. 实际做了什么

在原节点八张 A100-SXM4-40GB 上新增三个固定条件，共 15 个正式视频：
新 Dense、原封不动的旧 Cache、新 Q/K Kernel＋旧 Cache。
没有重开搜索，没有调阈值，也没有增加 prompt 或 seed。

SANA-Video 2B revision `db5f398b13ca086d09a50ce156c20527773841b1`；
832×480、81 帧、16 fps、50 steps、CFG 6，原定五个 prompt、seed 42。
每个视频仍为独立冷启动进程，沿用原来的一步预热；world size 1。
已有两轮的 Cache 和最终组合也重新看图，但没有重生成那些历史视频。

这是**有意复用历史配方的事后诊断**，不是“无历史经验、从零搜索”的新复现实验。
三个原生优化 Agent 的完整搜索没有重跑；本次仅创建一个全新、隔离的匿名视觉评审会话。

## 2. 速度与复现性

下表耗时是五个原生请求计时之和，不是五卡并行的墙钟时间；不含加载、内部预热和导出。

| 条件 | 五请求合计 | 相对本次 Dense | LPIPS mean / max | 本轮匿名复评 |
|---|---:|---:|---:|---|
| 新 Dense | 640.085 s | 1.000× | 不适用 | 参考 |
| 原样旧 Cache | 441.993 s | 1.448× | 0.082660 / 0.125047 | fail，medium |
| 新 Q/K Kernel＋旧 Cache | 374.949 s | 1.707× | 0.095721 / 0.155902 | fail，medium |

旧 Dense 是 640.020 s，本次仅变化 **+0.010%**。
旧 Cache 原计时为 440.115 s，重跑变化 **+0.427%**。
更强的复现证据是：**重跑的五个 Cache 视频，MP4 文件 SHA-256 全部与旧视频相同**；
LPIPS mean、max 和 39 个最终选中帧对也复现。
因此这次质量判断变化，不能解释成模型换了、生成随机漂移或重跑时画面变坏了。

组合的 1.707× 只是已测到的原始速度，**不是已通过质量验收的可用加速结果**。
它比六类搜索最终组合的 492.736 s 少 23.90% 请求时间，但两者不满足同质量比较条件。

## 3. 统一匿名复评结果

评审为全新隔离原生 `gpt-6.1-sol` 会话，沿用原模型／推理设置。
只提供不透明别名、原始 rubric、prompt／时间映射和真实图片；
不提供方法名称、速度、LPIPS、旧结论和历史搜索轨迹。

每组完整覆盖五个 prompt、每个 11 个对齐采样点，保持原有对比图像素。
六组共 **90 张 PNG 对比图、330 个对齐帧对**。
已核对原生会话确实接收全部图片，并把实际图片内容哈希、prompt、时间点、
可信工具回执和原始远端图片元数据逐项绑定；没有漏图、错配或内容哈希异常。

| 复评对象 | 原质量结论 | 本轮统一复评 | 主要失败 prompt |
|---|---|---|---|
| 旧 Cache `easycache_conservative_v1` | pass | fail / medium | 2：卧室；3：冰冻卫生间 |
| 旧最终组合 `integrated_packed_easycache_v1` | pass | fail / medium | 2、3 |
| 新保守 Cache `easy_runtime_window_t002` | pass | pass / none | 无 |
| 新最终组合 `qk_cast_easywindow002` | pass | pass / none | 无 |
| 本次原样旧 Cache | 新测试 | fail / medium | 2、3 |
| 本次 Q/K＋旧 Cache | 新测试 | fail / medium | 2、3 |

复评指出的主要问题：卧室窗帘／窗框及家具边缘有持续的模糊和偏移重影，
冰冻卫生间墙砖的霜纹、棱线和粗糙细节明显变平。其余三个 prompt 未判出新增明显缺陷。
主验收人也检查了代表性对比图，确认这些静态差异可见；没有据此声称完整视频的时间一致性已被证明。

历史评审将部分差异判为 low，旧最终组合甚至给出 none；本轮统一评审判为 medium。
这构成**相同产物上的质量验收分歧**，不是生成复现失败。
新评审仍然只是一个评审者，不能当作人工金标准，也不能据此估计评审错误率。
本轮规则是出现争议时不提升新点；不修改原报告来掩盖过去的 pass。

原版 lossy 路径没有固定 LPIPS 绝对通过阈值。LPIPS 必须完整计算，但不能用低分抹掉视觉失败。
保持原来全局 55 对采样帧上的分层＋最差选择规则；本次旧 Cache 选出 39 对，组合 38 对。
候选不同会导致最终选中帧对不同，因此不同候选的 LPIPS mean 也不是严格同一帧集上的效果量。

## 4. 验收边界

- 两个新点的正式 gate 均为 **reject**，原因及完整逐 prompt 结论见 `artifacts/OUTCOMES.json`。
- 原始五 prompt 生成、结构检查、工作负载观测、全局 LPIPS 和匿名视觉复评均完成。
- 每组五个正式请求均观察到 50 steps、100 次逻辑模型调用。逻辑调用数不是完整 DiT 真正执行次数；
  不由它反推出 Cache 精确命中次数。
- **新点的独立 objective verifier / fresh LPIPS reassessment 为 NOT_RUN**：
  预注册规定只对质量通过的新点执行；本次没有合格点，未强行推进到正式交付。
- 本轮没有撤销或重写历史机器可读记录。旧 Cache／旧组合的原 pass 与新 fail 应一起保留，
  后续经验检索应把它们标为“质量结论有争议”，而非无条件成功配方。
- 全部质量结论仅覆盖这五个 prompt 和 seed 42 的抽样帧。没有新增 seed、VBench、多评审者或完整视频人工评测。

### API 时间不能全算成网络延迟

评审会话共 16 次响应请求：11 次完成、5 次 502 transport error。
原生客户端重试后正常结束，全部实际模型回执为 `gpt-6.1-sol`。
请求累计 953.909 s，最长单次 286.097 s；失败请求本身累计 6.033 s。
这些时间包含模型推理、图像处理和网络传输；没有单独识别纯网络延迟。
因此不能把这 16 分钟全归因于 VPN。重试没有重新提交 GPU 视频，也未重复消耗候选预算。

## 6. 收尾、证据与下一步

八卡最终均为 0 MiB／0% 活动；新运行 UID 范围内没有残留进程。
不过 SSH 脱离启动的服务主进程退出后，留下 **1 个 PID 1 所有的 Z 状态条目**，不占显存。
因此总体生命周期清理标为 **REVIEW**，不能只看 UID 扫描的 PASS 就声称全部清理成功。
没有杀 PID 1、其他用户进程或历史僵尸进程。后续修复应采用可回收的服务父进程，不能靠重复 kill 僵尸条目。

远端附加证据包已重开并逐文件哈希核验：7,454 个文件，54,201,050 bytes；
SHA-256 `9c172bd048535ca2795d7a4ce49489620bb29d03b246bdaab126ed8731f334c2`。
原视频和源码回执保存在远端持久目录，模型权重没有下载或传回本机。

本轮结论不是“找到更快可用配方”，而是发现一个需要先解决的可靠性问题：
**搜索结果的速度可以稳定复现，但视觉验收会改变哪些点被认作有效 frontier。**
下一步应先固定／校准质量验收与争议处理，再做等质量的搜索对照；
不应把旧 Cache 不加条件写成可迁移的成功经验。本轮没有开始这项后续工作。
