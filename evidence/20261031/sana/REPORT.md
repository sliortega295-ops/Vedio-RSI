# 六类搜索与八卡完整闭环：正式结果

Run：`method-search-20261023-six-family-002`。日期：2026-10-23（下文时刻均为 UTC）。

## 结论先说

本轮已走完：修改并测试 Harness → 三个新原生会话六类初筛 → 启用一台机器八张 A100、Dense 与候选准备并行 → 搜索和反馈修改 → Master 独立验证 → 两次真实组合生成及完整验收 → 最终交付、经验写回、服务关闭。

最终选择 **Q/K 准备融合 + 中段 EasyCache**：五个请求的 native 时间之和从 **637.2719 s 降到 492.7363 s，1.2933×，耗时减少 22.68%**。Kernel 单独为 1.1707×，两个保留 Cache 点分别约 1.1041×。最终组合通过本轮原定 LPIPS 与 Master 原生视觉检查，但没有达到最低 1.5× speed tier，也不是论文完整结果复现。

整轮从 **16:41:13 到 19:40:35，2 小时 59 分 22 秒**。未达到此前“争取接近一小时”的性能愿望；本轮计划本身预留半天、不以到点截断。八卡服务窗口内 NVML 平均利用率 **10.58%**；同时有八个真实视频请求在执行的累计窗口只有 **58.56 s**。这次确实具备八卡共享队列和跨候选并行，但没有形成持续充足的 ready work。

这是一次**基础设施辅助闭合**的实验，不是完全无人值守：中途一次失败 worker 资源恢复；收尾一次 SSH 回执恢复，并修正一个报告接口角色映射。没有给实验 Agent 提供旧优化经验或配方，没有追加候选、重跑 Dense 或扩大预算。

工作流终态为 `COMPLETE`，来源/冻结/预算/验收证据核查通过。资源清理仍为 `REVIEW`：八卡已全部释放，原故障留下 5 个被 PID 1 接管的僵尸进程，不占 GPU 显存，但不能声称进程清理完全通过。

选中的固定来源：

- FLA bidirectional linear attention `dd222769550d320bbb67edf3d78ddd5b8cfabb4d`：已选中，但涉及精度变化，路由至 lossy lane；本轮**没有尝试**。

TeaCache、EasyCache、ToMe 本来就在冻结 Sol 菜单内。Liger、FLA 是外部实现来源，但对应融合/线性注意力机制也已在菜单中。**本轮没有证实一个菜单外新机制带来最终收益。** 外部仓库来源不等于新方法创新。

其余三类不是“完全没有搜”，而是初筛未建立可执行、源码完整且满足当前约束的适配路径：

- Sparse：检查的 SVG softmax 3D self-attention 不匹配当前 ReLU linear self-attention；这不能排除 cross-attention 或整个稀疏类别。SVOO 专用核心/离线 profile、PISA 代码许可等证据仍不完整。
- Quantization：检查的 Q-Diffusion 核心是反量化后普通 linear/conv，校准资产不在本轮缓存；NVFP4 目标硬件不符；Nunchaku 的源码/运行时/检查点适配未核实完成。不能据此推断 A100 上所有量化都不可行。
- Few-step：所查 DPM-Solver、UniPC 源码没有建立当前 SANA flow prediction 的转换关系；训练目标字段仍未知。另一 flow ODE solver 仅有论文级线索，未落实可执行适配。因此本轮全部实际视频仍为50步。

多个类别未达到“3种方法发现/2种源码检查”的目标，均保存了显式 shortfall，包含来源 API rate limit。TaylorSeer 来源许可未满足当前接入门槛，**没有完整 TeaCache/EasyCache/TaylorSeer 三家实测比较**。这是有边界的初筛闭环，不是穷尽搜索或完整方法覆盖。
